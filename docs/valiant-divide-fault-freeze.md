# VALIANT (GAME_BASIC88.D88) がエミュレータでフリーズする問題の解析と対処

- 対象: `GAME_BASIC88.D88` 収録「1. バリアント」(STARSHIP VALIANT, 1983, ALU Corp. / FLINT)
- 症状が出る環境: Neko Project II (np2) 系エミュレータ全般（Windows版 np2 本体、np2-wasm / np21 とも）
- 実機 (EPSON PC-386VR) では正常動作していた
- 解析日: 2026-08-18

## 症状

1. ゲーム起動直後、画面下部ステータス行の FUEL と TIME の数値が文字化けする
   （例: `FUEL 2(§U0   TIME 2(」Ii` のようにゴミ文字が表示される）
2. 直後（デモ/ゲーム開始時点）に画面が完全に停止する
3. STOPキーも効かない（BASICへBreakできない）
4. CPUクロックを2.5MHz〜10MHzに変えても同じ画面で停止（クロック非依存・決定論的）

## 調査方法（要点）

np2-wasm をブラウザで動かし、JavaScriptからエミュレータのWASMヒープ
（= エミュレートされたPC-98の全メモリ）を直接読み出して解析した。

1. BASIC側の調査: メニューをSTOPでBreakし `FILES` / `LIST` で構造を確認。
   メニューは `CHAIN "バリアント"` でローダーを起動。ローダーはプロテクトセーブ
   (`SAVE ,P`) されており `LIST` 不可だが、LOAD後のRAM上では復号済みのため、
   WASMヒープをスキャンして中間コードを直接読解した。内容は:

   ```basic
   1170 DEF SEG=&HB000 : BLOAD "VALI m.H86"   ' グラフィックデータをGVRAMへ
   1180 BLOAD "VALI s.H86",R                   ' 機械語本体をロードして実行
   ```

2. ハング箇所の特定: ヒープのスナップショット差分からCPUレジスタ構造体の
   位置を特定し、ハング中の CS:IP を4000回サンプリング。結果は以下の2点のみ:

   | CS:IP | 内容 |
   |---|---|
   | `0800:161B` | ゲーム機械語内の `F7 3C` = `IDIV word [SI]` |
   | `FD80:0166` | ROMの INT 0（除算例外）ハンドラ |

   → IDIV → 除算例外 → ハンドラ → 復帰 → 同じIDIV → … の無限ループと確定。

## 根本原因

### 原因1: フリーズ = 除算例外(INT 0)復帰アドレスのCPU世代差

x86の除算例外（ゼロ除算・商オーバーフロー）で、スタックに積まれる復帰アドレスが
CPU世代で異なる:

| CPU | INT 0 が積む復帰アドレス | IRETの結果 |
|---|---|---|
| 8086 / V30 (1983年当時のPC-98) | 次の命令 | 除算をスキップして続行 |
| 286以降 (エミュレータの動作) | 例外を起こした命令自身 | 同じ除算を再実行 → 無限ループ |

VALIANTの3Dワイヤーフレーム演算は、透視変換の `IDIV` がオーバーフローしても
「例外→そのまま続行」できる8086の挙動を前提に書かれている。np2/np21は286/386を
正しくエミュレートするため、逆に古いゲームが無限ループに陥る。

実機のEPSON ROMの INT 0 ハンドラ (`FD80:0166`) は単なるIRETではなく実処理を持つ
コードで、実機ではこれが対処していたとみられる。ただしnp2の機種設定を
`pc_model=EPSON` にしてもこのハンドラは機能しなかった（np2のEPSON固有I/O
エミュレーションが不完全なためと推測。検証済み・効果なし）。
また、np2のV30モード（DIPSW3 bit7）はV30世代のNEC ROMが前提で、
この286前提のEPSON ROMでは起動自体が不可（黒画面）だった。

### 原因2: FUEL/TIME文字化け = np2の286コア(i286c)固有の演算バグ

np21（i386コア）で起動すると FUEL/TIME は最初から正常な数値で表示された。
つまり文字化けはフリーズとは別問題で、np2のi286cコアにおける数値→文字列変換
ルーチン関連の命令挙動の不正確さが原因（np21のi386cコアでは発生しない）。

## 対処方法

`index.html`（np2-wasm同梱の自己完結ページ）に対して以下を実施:

### 1. エミュレーションコアを np2 (i286c) から np21 (i386c) に変更

→ FUEL/TIME の文字化けが解消。

### 2. BIOS ROM の未使用領域に「8086互換 INT 0 ハンドラ」を埋め込み

BIOS.ROM 内の 0xFF パディング領域（ROMオフセット 0x10A00 = 物理 F8A00h、
1555バイトの空きの一部）に、以下の66バイトのハンドラを配置:

- スタック上の復帰 CS:IP から命令を読み、セグメントプレフィクス
  (26/2E/36/3E) をスキップ
- オペコードが F6/F7 (DIV/IDIV系) であることを確認
- ModR/M バイトから命令長（ディスプレースメント0〜2バイト）を算出
- 復帰IPを命令の次のアドレスへ進めて IRET
  （= 8086/V30 の除算例外セマンティクスを再現）

```
55 8B EC 1E 56 50 53 FC  C5 76 02                 ; push bp/ds/si/ax/bx, cld, lds si,[bp+2]
AC 8A D8 80 E3 E7 80 FB  26 74 F5                 ; プレフィクススキップループ
3C F6 74 04 3C F7 75 1E                           ; F6/F7以外なら何もせず復帰
AC 8A D8 24 C0 3C C0 74  12 3C 40 74 0D 3C 80 74  ; ModR/M解析
08 80 E3 07 80 FB 06 75  02 46 46                 ; disp長ぶんSIを加算
89 76 02 5B 58 5E 1F 5D  CF                       ; 復帰IP更新、レジスタ復元、IRET
```

### 3. INT 0 ベクタのウォッチドッグ（JavaScript側、毎秒実行）

物理アドレス 0000:0000 の INT 0 ベクタを監視し、ROM標準ハンドラ
(`FD80:0166`) を指している場合のみ、埋め込みハンドラ (`F8A0:0000`) に
差し替える。

- リセットやCHAINでベクタが初期化されても1秒以内に自動再適用
- ソフトが独自に INT 0 をフックした場合は値が異なるため上書きしない
- ハング中に差し替えられた場合も、次の例外発生時点で脱出できる

## 検証結果

- VALIANT: FUEL 28090 / TIME 27933 と正常表示。デモが進行し、敵出現・
  スコア加算・FUEL/TIME減少を45秒以上確認。フリーズなし
- 回帰なし: ゲームメニュー、MOON BALL（ピンボール）デモ、テトリス
  (BPS版, 別D88) すべて正常動作

## 補足・一般化できる知見

- 1983年前後のPC-98ゲーム（特に機械語で演算するもの）が286以降の実機や
  正確なエミュレータでフリーズする場合、除算例外の世代差をまず疑うとよい。
  同時期のALU製ゲームなどで同様の症状が出ても、この修正で救済される可能性が高い
- MS-DOS環境ではDOS自身が INT 0 に独自ハンドラを設定するため顕在化しにくい。
  N88-DISK BASIC環境はROMのハンドラがそのまま使われるため露呈しやすい
- np2本体（Windows版等）で対処する場合は、V30モード＋V30世代のNEC ROMの
  組み合わせにするのが正攻法（np2の `v30patch.c` は8086式の
  `INT_NUM(0, 次命令IP)` を実装済み）。EPSON 286/386系ROMではV30モードは
  起動不可なので、本書のROMパッチ方式が有効
